# 常见问题

[返回 README](../README.md)

### 准不准？

先分两件事说。

**排盘对不对**：可以检验。程序有测试，也和独立算法对照过；离边界近的情况会给两张盘，不替你瞎选。测试只覆盖了有限的用例，通过不代表所有边界都绝对正确；早晚子等历法约定各家也不同，这里两种都给。

**解释灵不灵**：本项目不做这个承诺。八字是一套传统的解释体系，这里能保证的是：每条判断说清依据和把握，拿不准就并列两种读法或先问你，不把推测说成定论。

### 为什么问我那么多问题？

一个盘有两种说得通的读法时，用你经历过的事来校准，比让模型挑一种听起来顺的更老实。问题一次最多 5 个，可以跳过。不会问收入数字、病史或感情隐私。

### 报告里的 80% / 20% 是什么？

两种读法在固定计分规则下的倾向分。它是一种记账方式，不是“80% 的可能会发生”。

### 我在手机 App 上排的日柱和这里不一样？

最常见的原因有三个：

- **出生在晚上 11 点到 12 点之间。** 很多 App 从 23 点起就换日，这里两种口径都会给出。
- **没用真太阳时。** 程序会按出生地经度和均时差换算，城市偏西的话差几十分钟很常见。
- **出生时间离节气交界很近。**

如果三种都不是，欢迎开 issue，请用合成时间复现。

### 不会 Python 能用吗？

需要在电脑上装一次 Python 和依赖，[安装说明](install.md)里的命令可以直接照着复制粘贴。之后就在 Claude Code 或 Codex 里正常对话。

只用网页聊天的话，可以把 SKILL.md 和资料交给模型：

- 如果你另外在电脑上跑过程序，把完整事实包一起给它，它就能按这些事实解释，并注明事实包由你提供；
- 如果只有 App 上的四柱或截图，报告会标明“排盘未经本程序核验”，缺的大运、十神等不会由模型补算。

### 农历生日可以吗？

可以。要说清楚是不是闰月。

### 海外或港澳台出生？

可以。最好直接给出生地的经度和 IANA 时区名（比如 `America/Los_Angeles`），程序会处理当地的历史时区和夏令时。新疆出生请说明当时用的是北京时间还是当地时间。

### 只知道大概几点出生？

把范围告诉它，比如“下午 3 点左右，前后半小时”。程序会列出这个范围里可能的时柱，靠时柱的部分（子女、晚年）先不写死。

### 能看健康吗？

只写传统五行对应的日常保养方向，并注明不是诊断。不写病名，不预测疾病、寿命或事故。身体不舒服请看医生。

### 能合盘吗？

`scripts/synastry.py` 只列两张盘之间的干支关系事实，没有“合不合”的打分，也不预测感情走向。

### 会不会联网、要不要 API 密钥？

都不用。安装依赖时要联网下载，之后程序运行不联网。你用的 AI 工具本身怎么联网，与本项目无关。

### 可以拿来做商业服务吗？

代码是 MIT 许可，允许商用，但第三方数据和依赖有各自的许可证，见 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)。

对外提供命理类服务要遵守当地法规和平台规定，这一点需要你自己核查。

### 为什么默认用“早晚子分开”？

这是项目定下的展示顺序，参考王德峰讲座的口径。另一种口径也会一起给出，不存在“这里只认一种”的情况。
